# Android TV applications

Former skill: `androidtv_app`

Instructions for building an androidtv application.

=== Android TV Development Rules ===
- This is NOT mobile Android - TV uses D-pad navigation, NOT touch
- Use FragmentActivity (NOT AppCompatActivity) with Leanback library
- Write all dependencies with EXPLICIT versions: "dependency:1.12.0" not "dependency:"
- DO NOT modify settings.gradle.kts or create composite builds unless explicitly requested
- Keep Gradle project structure as initialized: any direct changes might break the project

=== XML Layout STRICT RULES ===
- EVERY View MUST have BOTH android:layout_width AND android:layout_height
- Valid values: "match_parent", "wrap_content", or "100dp"
- This applies to ALL elements: Button, TextView, ImageView, LinearLayout, etc.

=== TV Viewport & Overscan RULES ===
- TVs cut 8% of all sides (overscan) - content at screen edges will NOT be visible
- Assume the usable viewport is significantly smaller than 1920x1080 unless otherwise specified
- ALWAYS use landscape orientation

=== TV Layout Sizing RULES ===
- ALWAYS calculate available space BEFORE setting dimensions
- When using dimension ratios (like 1:1 for square): First check if height fits in available vertical space
- If grid width is 80% of screen (1536px on 1920px), height also becomes ~1536px - but TVs are usually only 1080px tall!
- Available vertical space = screen height - overscan top - overscan bottom - other UI elements
- NEVER set width percentage above 50-60% if using 1:1 aspect ratio - it will overflow vertically
- Add horizontal AND vertical Guidelines (not just top/bottom) to constrain all sides
- Constrain elements TO Guidelines, NOT to parent edges
- Test calculation: If width=60%, ratio=1:1, height=60% of screen width, will it fit in available height?

=== Focus & Layout Guidelines ===
- ALWAYS use landscape orientation: android:screenOrientation="landscape"
- Keep critical UI 48dp+ from screen edges (overscan-safe)
- Font sizes: minimum 18sp for body, 24-32sp for primary content
- Make all interactive elements focusable with visual feedback

=== Generated Code & Build Artifacts ===
- NEVER manually edit files in build/, generated/, or .gradle/ directories
- These files are auto-generated by Gradle plugins - manual edits will be overwritten or cause conflicts
- If generated code is wrong, fix the SOURCE file that generates it, then rebuild

=== Navigation Safe Args Rules ===
- Use the type-safe navArgs() delegate if necessary - it provides compile-time safety
- Args classes are GENERATED from nav_graph.xml - they ONLY contain properties for <argument> entries defined there
- When adding navigation with arguments: add ALL <argument> entries to nav_graph.xml FIRST, build the project, then write Kotlin code
- "Unresolved reference 'foo'" on args.foo means <argument android:name="foo"> is MISSING from nav_graph.xml - fix the XML, not Kotlin

=== Gradle Code Generation (Safe Args, Room, Hilt, ViewBinding) ===
- Source of truth is ALWAYS the annotation/XML, never the generated class
- After modifying source files that trigger generation, rebuild before writing code that depends on generated classes
